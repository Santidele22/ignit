# Responsive App & PWA Safe-Areas

Feature: Make the entire Ignit web app (`/biblioteca`, `/`, `/lecturas/[id]`, `/login`, `/registro`) fully responsive for mobile and desktop as a PWA-ready layout with bottom navigation bar on `/biblioteca`, collapsible mobile header on `/`, safe-areas, `100dvh`, ≥16px mobile inputs, and ≥44px touch targets (excluding manifest, icons, and Service Worker).
Branch: `feat/biblioteca-sala-lectura`

## Specs

- **S1**: Responsive `/biblioteca` mobile navigation (`<= 768px`) using a PWA bottom bar + compact topbar (`web/src/features/library/components/SalaTopbar.tsx`, `web/src/features/library/styles/biblioteca.css`). Topbar stays a single row (~56px + `env(safe-area-inset-top)`) with `熒 Ignit`, compact `+ Subir` button (≥44px), and a `☰` menu toggle (`aria-expanded`, `aria-controls="sala-mobile-menu"`, ≥44×44px) opening a compact menu panel with the online/offline toggle, palette switcher (`Noche azul` / `Original`), and user pill + `Salir` (closing on `Escape` or outside click). The 4 tabs (`En este dispositivo`, `Mi biblioteca`, `Catálogo`, `Mis aportes`) render as a fixed PWA bottom tab bar with crisp icons, short mobile labels, count badges, and `env(safe-area-inset-bottom)` padding, reusing the single accessible `role="tablist"` (no duplicate IDs, roving `tabindex`, `ArrowLeft`/`ArrowRight`). Move `header.app-top`'s `backdrop-filter` onto a `::before` pseudo-element so the header never traps the `position: fixed` bottom tab bar inside a filter containing block. Desktop (`> 768px`) remains unchanged.
- **S2**: Responsive `/biblioteca` layout, cards, inputs, and modals across mobile (`360px–767px`) and tablet (`768px–1080px`) in both `noche-azul` and `original` palettes (`web/src/features/library/styles/biblioteca.css`, `HeroDash.tsx`, `BookTomoCard.tsx`, `AportesList.tsx`, `UploadBookModal.tsx`, `EditBookModal.tsx`, `BibliotecaApp.tsx`): `min-height: 100dvh`, bottom clearance for the fixed bottom tab bar + `env(safe-area-inset-bottom)`, horizontal safe-area insets on `.shell`, ≥16px font-size on `.search-input` and `.field input/select/textarea` on mobile (preventing iOS Safari auto-zoom), ≥44px touch targets on mobile interactive controls (`.btn-edit-mini`, `.btn-ghost`, `.net-toggle`, `.palette-mini button`, `.chip`, `.btn-dl`, `.btn-primary`, `.btn-sec`, `.modal-close`, `.top-tab`, `.mobile-menu-toggle`), full-width `.search-input` on narrow screens, non-overflowing `.tomo-foot` in 1- and 2-column `.rejilla`, left-aligned mobile `.aporte-actions`, responsive `.hero-dash`/`.resume-card` stacking, and modals with `dvh` sizing, safe-area padding, and clean mobile `.modal-foot` button layout without inline flex-spacer glitches.
- **S3**: Responsive Landing (`/`) fixed header (`header.marcas`) and mobile layout (`web/src/features/landing/components/LandingHeader.astro`, `web/src/features/landing/client/initLanding.ts`, `web/src/features/landing/styles/landing.css`): on desktop (`> 860px`) keep the existing glass header; on `<= 860px` render a single-row fixed bar with `env(safe-area-inset-top)`, `熒 Ignit`, primary CTA (`Entrar` or `Mi biblioteca`), and an accessible menu button (`☰`, ≥44×44px, `aria-expanded`, `aria-controls="landing-mobile-nav"`) opening a glass dropdown panel with `Catálogo`, `Publicar`, `Vigilia`, `Offline`, `PaletteToggle`, and session action (`Instalar app` or `HeaderAuth`). Wire toggle/close (`Escape`, outside click, nav link click) inside `initLanding.ts` (zero new inline `<script>` tags so CSP stays intact). Ensure `.capa` top padding clears the fixed header + `env(safe-area-inset-top)` on 360px–860px without colliding with hero content, and mobile nav links/buttons have ≥44px touch targets.
- **S4**: Responsive Reader (`/lecturas/[id]`) safe-areas and mobile touch targets (`web/src/features/book/reader/reader-chrome.css`, `reader-panels.css`, `reader-stage.css`, `reader-vigilia.css`): `.topbar` respects `env(safe-area-inset-top/left/right)`, `.bottombar` respects `env(safe-area-inset-bottom/left/right)` so controls never collide with the iOS home indicator, mobile/coarse-pointer controls in `.bottombar` and `.selbar` meet ≥44px hit targets without horizontal overflow at 360px, and decks (`.chapter-deck`, `.timer-deck`, `.view-deck`) respect `dvh` max-heights and bottom safe-area insets.
- **S5**: PWA viewport and safe-area head metadata across all active routes (`web/src/app/layouts/BibliotecaLayout.astro`, `web/src/app/layouts/LandingLayout.astro`, `web/src/pages/lecturas/[id].astro`, `web/src/pages/login.astro`, `web/src/pages/registro.astro`): `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />`, `<meta name="theme-color" content="#04050a" />`, `<meta name="apple-mobile-web-app-capable" content="yes" />`, and `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent" />`. Add safe-area padding on `/login` and `/registro` containers and ensure auth form inputs (`web/src/features/auth/`) are ≥16px on mobile and submit buttons ≥44px tall. Explicitly out of scope per user decision: `manifest.webmanifest`, icons, and Service Worker.
- **S6**: Zero new inline `<script>` tags (CSP untouched), focused deterministic Vitest coverage for responsive navigation/behavior, and `pnpm test`, `pnpm astro check`, and `pnpm astro build` pass cleanly in `web/`.
